# Storyboard: PP-005 - Photographers lose booked dates to slow scheduling email tag and no-shows

Pain point: PP-005
Persona: wedding and portrait photographer scheduling clients by email and DM
Tier shown: free
Format: desktop
Seed: 5
Target length: 20-30 s

## Hook (first 1.5 s)

On-screen text (6 words or fewer): Still booking by email tag?
Why it stops the scroll: the first frame is the photographer's real calendar month with booked sessions already on it, so the viewer sees the destination (a week that fills itself) before the client side starts.
No logo in the first frame.

## Starting state

Fixture to seed (through the app UI and the app's own APIs, nothing by hand in the database):
- The demo org "Amara & Oak Photography" (slug amara-oak-photography) with availability rules Monday to Saturday 9:00 to 18:00 and three session types (Discovery Call, Portrait Session, Wedding Day), all shipped by the demo seed.
- `fixture()` cancels any stale widget booking left for the demo client by an earlier crashed run (POST `/api/bookings/{id}` from the logged-in page), in the current and the following month, so exactly one run owns the booking this take creates.
- `fixture()` checks `/b/amara-oak-photography` returns 200 and names the studio, and resolves one seeded demo booking's client name from `/api/bookings` so step 1 can hover a real chip on any calendar month.
- No database writes beyond what the app's own APIs do.

Screen the recording opens on: `/dashboard/calendar`, the current month grid with the seeded bookings on it, no dialog open.
Account and org: the demo login from `growth/.env.local`.
Recording target note: recorded against the local dev server (`GROWTH_STAGING_URL=http://localhost:5173`), same code as staging, because staging credentials were not configured in this environment. The booking page is `/b/{org slug}`; the calendar widget renders inside a same-origin iframe (`#snap-booking-frame`), so the take drives it with frame-scoped locators and the performer's page-level mouse (boxes come back in main-frame coordinates).

Teardown:
- `teardown()` cancels the booking this run created (the take captures the `bookingRef` from the widget's POST `/api/embed/bookings` response) and verifies the month list no longer returns it.
- Canceling a disposable demo booking emails the demo client (captured to disk on the local target, never delivered); the slot frees for the next run.

## Steps

| # | Caption (6 words or fewer) | Action (performer calls: move, hover, click, type, select, scroll, focus, settle, hold) | Focus element (the camera zooms on the FIRST boxed action of the step) | Approx duration |
|---|---|---|---|---|
| 1 | Your week is already true | settle on the calendar month, `move` and `hover` the heading, then `hover` the day cell holding a seeded demo booking chip | the month heading, then the demo booking chip | 4 s |
| 2 | One link does the asking | `navigate` to `/b/amara-oak-photography`, settle on the hero, `scroll` the booking widget into view, `hover` the Portrait Session card | the hero title, then the Portrait Session card | 5 s |

Rules for every step: real clicks, typed text, eased scrolling, a settle pause after each new screen.
Widget interactions use `page.frameLocator("#snap-booking-frame")` locators; `focus` inside the iframe never uses `tight: true` because tight boxes measure frame-relative.

## The payoff shot

Step 4 into step 5: the widget's "You're booked!" confirmation with the checked time, then, back in the dashboard, the day cell carrying the new "Nora Example" chip and the day panel's booking card for the same slot.
Held for at least 1.5 s with the camera pushing in (label `payoff`).
It proves the chase is gone: the client chose a real opening from live availability and the session landed on the studio calendar without one email.
